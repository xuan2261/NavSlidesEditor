## 4. Điểm mạnh (evidence-based)

1. **Worker isolation** — parser fork, heap cap (`PARSER_MAX_OLD_SPACE_MB=1024`), timeout 60s, SIGTERM→SIGKILL, cancel AbortSignal. Host process không chết theo OOM parser dễ dàng.
2. **Zip-bomb defense** — không tin `uncompressedSize`; stream measure + cumulative budget 500MB, entry cap 5000, file cap 100MB.
3. **Async UX** — 202 + SSE + poll fallback khi `EventSource` lỗi; concurrency reservation **trước** multer (tránh race upload khi busy).
4. **Media hardening** — extension allowlist + magic sniff (`file-type`); external URL host allowlist; background scheme gating (`javascript:`, protocol-relative blocked).
5. **HTML sanitize** — DOMPurify allowlist + post-process href protocol + shared style sanitizer; acceptance tests chặn dangerous CSS/URL.
6. **Mapper modular** — split dưới `mapper/` (presentation/shape/image/table/group/diagram/media/utils); golden-master + property/geometry drift tests.
7. **Fidelity ops** — corpus harness, OOXML chart/SmartArt evidence vs mapped count, warning summary cho user.
8. **Test density** — 374 tests green trên suite import; route + job manager có coverage.

## 5. Findings

### Critical

*Không có finding Critical chặn merge cho model single-user hiện tại.*  
Các lỗ hổng auth/job IDOR được **document intentional** trong route; README security model cũng chấp nhận single-user self-host.

### Important

| # | Finding | Evidence | Impact | Recommendation |
|---|---------|----------|--------|----------------|
| I1 | **Memory amplification** | `pptx-guards` `readFile` + JSZip full load + re-inflate measure; worker `readFile` lại + `imageMode:'base64'`; job giữ full `result` (presentation) trong Map 10 phút; SSE `JSON.stringify` full payload | Deck 50–100MB có thể nhân 3–10× RAM (host + worker + IPC + job). Risk OOM / GC thrash. | Stream/zip disk path; parser `imageMode` path/ref thay base64; job result chỉ giữ presentationId sau khi persist; hoặc persist result to disk + stream-by-id |
| I2 | **Acceptance criteria không chạy trên import production** | `assertPresentationAcceptance` chỉ trong corpus tester, không gọi từ `importPptxFile` | Unit/corrupt parser output có thể lọt resolution sai / raw units / dangerous tokens nếu sanitize regress | Gọi acceptance gate trước `completeJob` (fail soft → warning hoặc 422) |
| I3 | **Job IDOR / no per-job secret** | Comment trong `pptx-import.js` L72–77; `GET/DELETE /jobs/:id` chỉ UUID | Multi-tenant: đoán UUID khó nhưng leaked jobId = đọc full deck / cancel | Trả `jobSecret` lúc create; require header/query; bind job→session |
| I4 | **`colorValue` không sanitize CSS color** | `utils-color.js` trả string thô; table có `sanitizeCssColor` riêng; shape/image/bg dùng `colorValue` | Malicious PPTX color `red; expression(...)` có thể lọt JSON; phụ thuộc `resolveColorField` phía client | Reuse `sanitizeCssColor` cho shape/line/bg/image borders |
| I5 | **Doc drift EMF/WMF** | Report/docs: “preserved with limited browser support”; `map-image.js` L36–48: **placeholder** `unsupported-image` | User/ops expectation sai | Cập nhật docs + fidelity report cho behavior hiện tại |
| I6 | **Background `data:image` inline ≤5MB trong presentation JSON** | `gateBackgroundImageSrc` | Bloat JSON presentation; không qua media dedup `/uploads` | Persist background images như element images |

### Suggestions

| # | Finding | Note |
|---|---------|------|
| S1 | HomePage `JSON.parse(event.data)` không try/catch | SSE malformed → unhandled rejection; wrap try/catch |
| S2 | Client retry busy `72 × 5s ≈ 6 phút` | UX treo; hiển thị countdown / cancel |
| S3 | Cancel mid-map: media đã `persistDeduped` trước abort có thể orphan | Acceptable; optional GC by jobId prefix |
| S4 | Transition mapping lossy (nhiều type → fade/slide) | Expected; document explicitly |
| S5 | `checkCRC32: false` | Trade-off speed; OK if measured inflate trusted |
| S6 | `Uint8Array.from(buffer)` khi magic-check media | Extra copy; dùng buffer trực tiếp nếu API cho phép |
| S7 | Chart/SmartArt native gaps chỉ warning | Correct degrade; surface in UI more prominently (đã có summary) |
| S8 | `MAX_MEDIA_SIZE` 200MB > file 100MB | Inconsistent; align caps |

## “Đúng” nghĩa là gì trong codebase này?

Pipeline đúng theo thiết kế:

```
.pptx  →  parse (pptxtojson)  →  map → NavSlides JSON  →  lưu presentation  →  edit
```

**Đúng** =:

- Element chính được map sang type NavSlides tương ứng  
- Tọa độ scale ổn (median drift thường &lt;1px trên nhiều deck)  
- Text editable, media vào `/uploads`  
- Lỗi/object lạ → placeholder + warning, **không crash silent**

**Không “đúng 100% PowerPoint”** = layout/theme/chart/SmartArt/vector Office có thể lệch hoặc mất chi tiết — đó là trade-off của editable import, không phải pure screenshot.

## Bạn nên kỳ vọng thế nào khi dùng thật?

1. **Slide bài giảng / báo cáo** (text, shape, ảnh, bảng) → **dùng được**, fidelity tốt trên corpus thực (`Bai_2_*`, `STTre_Duc`).
2. **Deck nặng chart/SmartArt/EMF** → import chạy, nhưng **một phần object** thành shape/placeholder; có warning.
3. **Import rồi export PPTX** → file mới “mở được / ổn”, **không** clone bit-exact.
4. **So visual với PowerPoint** → gần, không pixel-perfect (đặc biệt group rotate, line, image property ~70–84% trên một số deck).

- **Không — nếu “đầy đủ” = mọi thứ trong PowerPoint import 1:1 không mất mát.**

Đó là **feature mature có giới hạn có chủ đích**, không phải half-built stub.

## 1. Sự thật cứng (trước khi “làm thế nào”)

**“Mọi thứ trong PowerPoint, import 1:1, không mất mát” theo nghĩa editable NavSlides hiện tại = gần như không khả thi.**

Lý do không phải “code dở”, mà **model dữ liệu khác nhau**:

| PowerPoint (OOXML) | NavSlides hiện tại |
|--------------------|--------------------|
| Slide master / layout / placeholder inheritance | Flat slides + elements |
| Theme color scheme + style inheritance | Theme string + local styles |
| Freeform geometry, EMF/WMF, ink | Shape/SVG/image subset |
| Chart full (combo, 3D, trendline…) | Chart.js subset |
| SmartArt tree + layout algorithms | Flatten shapes |
| Animation timeline, triggers, morph | Fragment timeline khác model |
| Embedded fonts, OLE, ActiveX, macros | Không |
| Exact text frame autofit/columns | Heuristic `_pptxImportMeta` |
| Group nested + non-uniform scale | Flatten + matrix xấp xỉ |

Parser `pptxtojson` **đã lossy** (upstream cũng nói style ≠ source). Mapper lại lossy lần 2 sang 19 element types. Export hybrid (raster fallback) cũng lossy lần 3.

Repo từng ghi nhận: *“full fidelity” chưa operationalize metric → build trước, đo sau* (`docs/journals/260425-1637-pptx-full-fidelity-completion.md`).

**Kết luận:** 1:1 tuyệt đối **chỉ đạt được nếu đổi định nghĩa sản phẩm**, không chỉ “fix mapper thêm”.

---

## 2. Ba định nghĩa “1:1” — phải chọn 1 (hoặc hybrid)

Đây là quyết định quan trọng nhất.

### A. Visual 1:1 (pixel / perceptual)

**Nghĩa:** Mở slide import trông **y như** PowerPoint khi present.

| Cách | Ưu | Nhược |
|------|----|-------|
| Render slide bằng LibreOffice/PowerPoint COM → PNG/SVG per slide | Dễ đạt visual | Không edit text/shape |
| Object-level: native object nếu map được, else raster crop | Visual + một phần edit | Edit object raster mất |
| Giữ nguyên `.pptx` blob + viewer (OnlyOffice/Collabora iframe) | Gần 100% PP | Không phải editor NavSlides |

**Metric verify:** SSIM / LPIPS / pixel diff vs reference screenshots (PowerPoint/LibreOffice export).

### B. Semantic editable 1:1 (mọi object edit được, không mất data)

**Nghĩa:** Mọi phần tử vẫn chỉnh được như PowerPoint.

Yêu cầu gần như **reimplement PowerPoint model** trong NavSlides (master, theme, full geometry, animation…). Đây là multi-năm, team lớn (OnlyOffice/LibreOffice scale).

**Metric:** OOXML feature coverage matrix 100% + round-trip XML equality (gần bất khả với model hiện tại).

### C. Package 1:1 (zero-loss archive)

**Nghĩa:** Không đụng OOXML; import = attach file gốc; “edit” = edit bên trong package hoặc round-trip qua engine ngoài.

**Metric:** SHA256 gốc = SHA256 lưu; present qua engine ngoài.

## 3. Đường realistic cho NavSlides: **Hybrid Fidelity** (khuyến nghị)

Industry pattern (Google, Canva-style import, exporter của chính bạn đã hybrid):

```
                    ┌─────────────────────────────┐
  .pptx ──parse──►  │  Layer 0: keep raw package   │  (optional, zero-loss recover)
                    │  Layer 1: OOXML scene graph  │  (canonical intermediate)
                    │  Layer 2: NavSlides editable │  (best-effort map)
                    │  Layer 3: visual fallback    │  (raster/SVG per object/slide)
                    └─────────────────────────────┘
```

### Mục tiêu sản phẩm có thể ship

> **Present: visual ≥ 99% SSIM so với PowerPoint.**  
> **Edit: mọi text/table/image/shape phổ biến editable.**  
> **Object không map được: vẫn thấy đúng (raster), tagged “locked visual”, có nút “replace/edit as image”.**  
> **Zero-loss: luôn giữ `original.pptx` sidecar để re-export/re-import.**

Đây **không** phải “mọi thứ editable như PP”, nhưng **là** “không mất mát **nhìn thấy** + không mất file gốc”.

Nếu bạn **khăng khăng** mọi object editable 1:1 → chọn OnlyOffice/Collabora/MS Graph API, không mở rộng mapper hiện tại.

## 4. Làm thế nào — kiến trúc cụ thể

### Phase 0 — Operationalize “1:1” (1–2 ngày)

Chốt bằng `/ck:predict --chain probe`:

1. Visual SSIM ≥ X trên corpus?
2. Editable coverage ≥ Y% object types?
3. Round-trip XML / chỉ visual?
4. Có được giữ file gốc không?

**Deliverable:** `docs/pptx-fidelity-sla.md` với 3 số đo cứng.

### Phase 1 — Reference oracle (bắt buộc)

Hiện corpus so **parser → mapper**, không so **PowerPoint pixels**.

Làm:

1. Render reference mỗi slide bằng **LibreOffice headless** (hoặc PowerPoint COM trên Windows CI):
   ```bash
   soffice --headless --convert-to png --outdir ref/ deck.pptx
   ```
2. Render NavSlides present/export HTML → screenshot (Playwright — đã có browser audit).
3. Metric: `mean SSIM`, `max |Δ|`, per-slide fail list.

**Đây là metric cho `/ck:loop`.** Không có oracle pixel thì “1:1” chỉ là cảm tính.

### Phase 2 — Intermediate OOXML scene graph (thay vì tin `pptxtojson` output)

| Việc | Lý do |
|------|--------|
| Parse quan hệ slide: masters, layouts, placeholders resolve | Hết mất text từ layout |
| Theme color / font scheme resolve | Màu “schemeClr” đúng |
| spTree full: nvSpPr, xfrm, geom, blipFill, ln | Geometry/line chính xác hơn |
| Chart XML (`c:chart`) → series native | Hết “chart = shape” |
| Diagram data/layout/drawing | SmartArt bớt flatten mù |
| Giữ sidecar `_ooxml` / raw part refs | Không vứt data chưa map |

Có thể:

- **Option 2a:** Fork/extend `pptxtojson` + custom post-pass OOXML (nhanh hơn).
- **Option 2b:** Parser riêng OOXML (JSZip + fast-xml-parser) — kiểm soát 100%, effort lớn.
- **Option 2c:** Engine ngoài (LibreOffice UNO, Aspose, Syncfusion) — mua/dependency nặng.

Với mục tiêu 1:1 visual + partial edit: **2a + raster fallback** thường ROI tốt nhất.

### Phase 3 — Dual representation per object

Mỗi element import:

```js
{
  type: 'text' | 'shape' | ...,  // editable if confident
  // ...nav fields
  _pptxSource: {
    fidelity: 'exact' | 'approx' | 'visual-only',
    ooxmlPath: 'ppt/slides/slide1.xml#...',
    visualFallbackUrl: '/uploads/....png', // nếu approx/visual-only
  }
}
```

Render rule:

- `exact` / `approx` → render NavSlides.
- `visual-only` → hiện image fallback (layout đúng), lock edit hoặc “edit as picture”.

**Mất mát data?** Không — visual + optional raw package.  
**Mất edit?** Chỉ object chưa map.

### Phase 4 — Visual fallback pipeline (chìa khóa “không mất mát nhìn thấy”)

1. Per-slide full raster (baseline safety net).
2. Per-object bbox raster khi mapper confidence thấp (chart/SmartArt/EMF/ink).
3. EMF/WMF → SVG/PNG qua LibreOffice/Inkscape/ImageMagick (thay placeholder trống).

Exporter của bạn **đã hybrid reverse**; import cần **cùng triết lý**.

### Phase 5 — Expand editable surface (loop theo metric)

Thứ tự ROI (từ gap corpus/docs hiện tại):

| # | Gap | Metric loop |
|---|-----|-------------|
| 1 | Chart native từ OOXML | `nativeChartImported / ooxmlChartEvidence ≥ 0.95` |
| 2 | EMF/WMF → PNG | `unsupported-image placeholder count = 0` |
| 3 | Master/layout text | text count match vs OOXML resolved tree |
| 4 | Theme colors | color SSIM / sampled fills |
| 5 | SmartArt | visual SSIM region + structure score |
| 6 | Group non-uniform / line endpoints | geometry median drift ≤ 1px, max ≤ 3px |
| 7 | Animation (nếu cần) | timeline event coverage |
| 8 | Embedded fonts | font-face match or subset upload |

Mỗi mục = 1 `/ck:loop` với **Verify = số**, Guard = `npm run test:corpus` + unit không regress.

### Phase 6 — Zero-loss package sidecar

```
presentation.json
original.pptx          # byte-identical upload
import-manifest.json   # mapping elementId ↔ ooxml node, fidelity flags
```

“Không mất mát” tuyệt đối ở mức file: user luôn tải lại gốc.  
Re-export policy: *prefer original package parts where unedited*.

## Ba hướng có thể đạt SLA (phải chọn 1 trục)

### Hướng A — **Embed engine ngoài** (ROI tốt nhất cho “như PowerPoint”)

Ví dụ: **Collabora Online / OnlyOffice** (hoặc MS Graph + desktop PP automation).

- View + edit gần native PowerPoint  
- Giữ file gốc tự nhiên

|----|--------|

| Visual + edit do engine lo | Íp riêng, auth, deploy phức tạp |

**Phù hợp nếu:** “1:1 không mất mát” **quan trọng hơn** editor tip-tap hiện tại.

### Hướng B — **OOXML-native trong NavSlides** (tự xây model đầy đủ)

- Intermediate scene graph = gần full OOXML (master, theme, spTree, chart, diagram, animation…)  
- Editor/render NavSlides **mở rộng** tới model đó  
- LibreOffice/PP chỉ để **oracle đo**, không phải runtime  

| Ưu | Nhược |
|----|--------|
| Vẫn là sản phẩm NavSlides | Effort **lớn** (năm / team), gần reimplement PPT |
| Kiểm soát 100% | Chart/SmartArt/animation mỗi mảng là project riêng |

**Phù hợp nếu:** Muốn stack tự chủ, chấp nhận lộ trình dài, ship từng gate.

### Hướng C — **Hybrid tạm + zero-loss package** (không đủ SLA của bạn nếu dừng ở đây)

- Map được → editable  
- Chưa map → ảnh **tạm**, có ticket “thay bằng editable”  
- Luôn giữ `original.pptx`  

Bạn đã nói **không chấp nhận “chỉ ảnh mãi”** → C chỉ là **cầu** trong roadmap B/A, **không** phải đích.

## Lộ trình khuyến nghị nếu giữ SLA đúng chữ

**Chọn trục trước: A hoặc B.**

### Nếu chọn **A — Engine**

1. Spike Collabora/OnlyOffice self-host + mở `.pptx`  
2. Lưu presentation = `original.pptx` + metadata NavSlides (title, tags, live…)  
3. “Import” = đăng ký file gốc + mở trong engine  
4. Gate: so screenshot engine vs LibreOffice/PP  
5. NavSlides canvas chỉ dùng cho deck native; PPTX đi path riêng  

### Nếu chọn **B — Native OOXML**

1. **Phase 0 — SLA + oracle**  
   - Script: LibreOffice/PP → PNG từng slide  
   - Playwright present NavSlides → PNG  
   - Fail nếu SSIM &lt; ngưỡng (vd. 0.99)  

2. **Phase 1 — Zero-loss package**  
   - Mọi import lưu `original.pptx` + manifest  
   - Re-download gốc luôn được  

3. **Phase 2 — Scene graph OOXML** (không tin output lossy của pptxtojson làm nguồn sự thật)  
   - Resolve master/layout/placeholder  
   - Theme colors/fonts  
   - Full spTree + media  

4. **Phase 3 — Editable primitives parity**  
   - Text/shape/line/image/table đạt visual + edit gate  

5. **Phase 4 — Chart native editable**  
   - `c:chart` → model chart đủ series; không placeholder  

6. **Phase 5 — SmartArt editable**  
   - diagram data/layout → structure edit được  

7. **Phase 6 — Media vector (EMF/WMF)**  
   - Convert có kiểm chứng hoặc path render vector; không “unsupported” vĩnh viễn  

8. **Phase 7 — Animation / transition parity** (nếu có trong nguồn)  

9. **Mỗi phase:**  
   - Metric số + corpus  
   - Gap = test đỏ, không warning “OK”

## Metric gợi ý (để “đo được”)

```text
V1  mean SSIM(import_slide, reference_slide) >= 0.99
V2  không slide nào SSIM < 0.97
E1  mọi object class trong OOXML evidence có counterpart editable
E2  chartEvidence - nativeEditableChart == 0
E3  smartArtEvidence - nativeEditableDiagram == 0
E4  placeholderCount (permanent) == 0
P1  original.pptx tồn tại và hash khớp upload
R1  round-trip policy: re-export không mất object đã import (định nghĩa sau Phase 2)

```

## Giải thích chỗ “đo / claim” (và native)

Bạn chọn **B = native** → app **không** nhúng PowerPoint/Collabora/OnlyOffice khi user import.

Còn câu “so với PowerPoint/LibreOffice” có **hai tầng**:

| Tầng | Là gì | Có phải “phụ thuộc sản phẩm”? |
|------|--------|-------------------------------|
| **Runtime** | User mở/sửa slide trong NavSlides | **Không** third-party office |
| **Đo kiểm (oracle)** | Làm sao biết “trông đúng”? | Chỉ **test/CI**, không ship trong app |

**Đề xuất đã đưa vào plan (V-01) — khớp “native”:**

1. Maintainer (máy dev) **một lần** xuất ảnh slide chuẩn từ PP/LO → commit **golden PNG** vào repo (như fixture test).  
2. CI chạy NavSlides present → chụp ảnh → **SSIM so với golden**.  
3. App user **không** cài/gọi LO.

Vậy:

- Sản phẩm = **100% native** (đúng ý bạn).  
- Vẫn **đo được** visual (không chỉ corpus semantic 100%).  
- LO/PP = công cụ làm golden **offline**, không phải dependency runtime.

Ngôn ngữ claim an toàn:

> “Import đạt SSIM ≥ ngưỡng so golden (nguồn tham chiếu Office) + object editable theo metric E*; runtime thuần NavSlides.”

Không claim: “pixel = PowerPoint trên máy user” nếu không có PP trong CI.
