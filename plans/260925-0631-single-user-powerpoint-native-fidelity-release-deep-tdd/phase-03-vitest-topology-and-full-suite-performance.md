## Goal/Overview

Replace the current globally serialized, globally jsdom Vitest execution with
three explicit projects:

1. `client-jsdom`;
2. `node-parallel`;
3. `node-serial`.

Prove exact test inventory equality before enabling the topology. Preserve merged
coverage thresholds and feature-inventory JSON semantics. Treat a 30% median
wall-clock improvement as the optimization target until fresh profiling exists.
The release hard gate is a checked-in absolute CI wall-clock budget derived from
measured CI-equivalent runs, plus zero test-inventory, pass/skip, or coverage
loss.

Current performance constraint:

- `vitest.config.mjs` sets `environment: 'jsdom'` and
  `fileParallelism: false` for the entire repository.
- A historical full-unit run took 1,227.75 seconds for 518 passed files, one
  skipped file, 4,196 passed tests, and three skipped tests.
- A later report records 1,419/1,419 passed suites and 4,748 tests. Counts use a
  different reporter/model and must not be compared without a fresh canonical
  inventory.
- Static planning inventory currently finds 586 non-E2E `*.test|*.spec` files:
  270 under `client`, 224 under `server`, 34 under `shared`, 22 under `scripts`,
  and 36 under `tests`; 27 files carry an explicit Node environment directive.
  This count must be regenerated by the implementation script, not hard-coded as
  permanent truth.

## Scope and Non-Goals

### Scope

- One canonical lane classifier shared by config, inventory test, and runner.
- Exact union/equality checks:
  - every discovered non-E2E test belongs to exactly one lane;
  - no overlap;
  - no omission;
  - no duplicate execution.
- jsdom only for browser/component/editor tests that require it.
- parallel Node execution for pure/shared/script/server tests without global
  mutable state.
- serial Node execution for storage, process lifecycle, ports, singleton state,
  package-store writer locks, child processes, and other proven hazards.
- Per-worker storage roots for parallel lanes.
- One merged V8 coverage result with existing include/exclude rules and thresholds:
  lines 33, branches 28, functions 26, statements 33.
- Same JSON reporter output path/shape required by the feature matrix.
- Same-host before/after benchmark with a predeclared measurement protocol.
- Baseline capture before any RED topology test or config change. If repository
  policy forces the RED tests into the same commit, that commit must also add an
  immutable byte-for-byte legacy topology config and run old/new against it.

### Non-Goals

- No test deletion, skip, timeout inflation, assertion weakening, or coverage
  threshold reduction.
- No Playwright topology changes.
- No production behavior change except test-only environment setup.
- No broad rewrite of test files solely to make them parallel.
- No promise that all Node tests become parallel. Correct serialization wins
  over speed.
- No new test framework or coverage provider.
- No performance claim based only on the historical 1,227.75-second run.
- No hard failure solely because the initial safe split misses 30%; profile first,
  retain the measured absolute budget, and open separately reviewed optimization
  work without weakening completeness.

## Key Insights

1. Global jsdom creates avoidable startup and memory cost for server/shared tests.
2. Global `fileParallelism: false` serializes hundreds of independent files.
3. Current config gives every worker the same invocation-level
   `SLIDES_DATA_DIR`/`SLIDES_UPLOADS_DIR`. Parallel storage tests require
   worker-specific roots established before production storage imports.
4. The existing storage-isolation test currently proves one invocation root
   shared across two fork workers. Its expectation must deliberately change for
   parallel lanes: each worker gets an isolated root; serial tests may share one
   lane root because only one worker exists.
5. File-path classification alone is insufficient for serial hazards. Use a
   reviewed serial registry plus a hazard guard that flags known storage/process
   patterns outside the serial lane.
6. Coverage must be produced by one multi-project invocation or merged from
   disjoint lane reports with strict file-map validation. Concatenating text
   summaries is not merged coverage.
7. Benchmark comparison is invalid unless baseline and optimized receipts carry
   the same canonical test inventory hash. “Same number of tests” is insufficient.
8. Performance policy has two layers:
   - target: at least 30% median improvement after safe profiling;
   - hard release gate: total CI-equivalent Vitest wall time must not exceed the
     numeric `maxWallSeconds` in a checked-in measured budget receipt, and test
     inventory/pass/skip/coverage cannot regress.

## Requirements

### Functional

1. Create canonical lane definitions consumed by all Vitest entry points.
2. `client-jsdom`:
   - environment `jsdom`;
   - existing pointer-event setup;
   - file parallelism enabled;
   - excludes E2E and all Node-only files.
3. `node-parallel`:
   - environment `node`;
   - `pool: forks`;
   - bounded worker count, defaulting from CPU/CI policy;
   - unique data/uploads root per fork;
   - excludes serial hazard registry.
4. `node-serial`:
   - environment `node`;
   - one fork/worker;
   - `fileParallelism: false`;
   - includes all reviewed stateful hazards.
5. Inventory equality must compare canonical discovery with project union before
   test execution.
6. Inventory output records file path, lane, reason, environment, serial reason,
   and source hash.
7. Coverage uses one final `coverage/` directory and retains HTML, LCOV, text,
   and JSON summary outputs.
8. `npm run test` runs the three-project topology.
9. `npm run test:coverage` runs the same inventory with merged coverage.
10. `npm run test:inventory` validates equality without running the full suite.
11. `npm run test:benchmark` records machine/runtime/config/test-inventory hashes,
    lane durations, peak memory when available, and total wall time.
12. Feature-inventory JSON continues to be produced by a supported command.
13. Baseline ordering:
    - capture the legacy inventory, coverage, counts, config hash, and three
      timings before writing RED topology tests;
    - commit/hash the baseline receipt and immutable legacy config;
    - only then add failing topology tests.
14. Acceptance performance:
    - median of at least three fresh old-topology runs;
    - median of at least three optimized-topology runs;
    - same commit, dependencies, Node version, host power mode, and browser
      installation state;
    - identical canonical inventory hash for old and new;
    - record whether improvement reaches the 30% target;
    - derive a numeric CI `maxWallSeconds` after profiling from at least five
      CI-equivalent optimized runs, with documented runner class and bounded
      variance margin;
    - fail release CI above `maxWallSeconds`, on any missing/duplicate test, any
      increased skip, any failed test, or any coverage threshold/source-map loss.

### Non-Functional

- No production data directories used by tests.
- No cross-worker port collision.
- No snapshot or fixture write from parallel workers unless unique.
- Worker count bounded in CI to avoid memory thrash.
- Windows and Linux path normalization deterministic.
- Test-order dependence detected by repeated/shuffled focused runs.

## Architecture/Data Flow

```text
filesystem discovery
  -> canonical classifyVitestFile(path, source)
       -> client-jsdom
       -> node-parallel
       -> node-serial
  -> inventory equality guard
  -> Vitest multi-project run
       -> per-worker isolated test roots
       -> lane-specific reporters
  -> one merged coverage map
  -> threshold evaluation
  -> canonical JSON result for feature inventory
  -> benchmark receipt
```

Classification precedence:

1. excluded paths (`node_modules`, build output, coverage, worktrees, E2E);
2. explicit environment directive;
3. serial registry/hazard pattern;
4. client component/browser path -> jsdom;
5. remaining server/shared/scripts/unit -> Node parallel;
6. unknown path -> fail inventory, never silently default.

6. Assert current config does not define the required three project names.
7. Assert current `fileParallelism: false` global setting violates target topology.

## Implementation Steps

1. Verify the pre-RED baseline receipt and legacy config hash:
   - exact commit;
   - Node/npm/Vitest versions;
   - CPU/RAM/OS;
   - test inventory hash;
   - three run durations;
   - pass/skip counts;
   - coverage summary.
2. Refuse comparison if current discovery differs from the baseline inventory
   hash for reasons other than the intentionally added topology contract tests.
   For timing, run both legacy and new configs against an explicit frozen
   inventory that excludes the new topology-only self-tests from both sides.
3. Implement canonical discovery and classification.
4. Start the serial registry conservatively with tests that:
   - mutate file-backed storage or package-store state;
   - acquire writer locks;
   - bind fixed ports or start the full server;
   - mutate `process.env` across module imports;
   - use global/singleton socket or room managers;
   - spawn/kill process trees;
   - depend on deterministic global mock order.
5. Add a hazard scanner that fails when common storage/server/process imports
   occur in `node-parallel` without an explicit reviewed exemption.
6. Move temp-root ownership from config evaluation into setup code that runs
   before each worker imports storage.
7. Use fork workers for Node parallelism so process IDs provide an additional
   isolation boundary. Include lane/invocation/worker identity in root names.
8. Add cleanup on normal exit and best-effort cleanup after failures. Cleanup
   may remove only the current worker-owned root.
9. Configure projects with bounded workers:
   - local default: min(`logicalCpu - 1`, reviewed cap);
   - CI: explicit cap based on runner memory;
   - serial: one.
10. Preserve jsdom pointer-event setup only in `client-jsdom`.
11. Run inventory equality before every full test/coverage command.
12. Produce coverage in one multi-project run where supported. If Vitest emits
    per-project maps, merge V8/Istanbul maps by filename and assert:
    - disjoint execution inventory;
    - union contains every covered source file;
    - no source coverage record is overwritten by a later lane;
    - final thresholds equal the old config.
13. Preserve HTML, LCOV, text, and JSON summary reporters.
14. Preserve feature-inventory result generation with one canonical merged JSON
    report. Add a schema contract before changing CI consumers.
15. Run each lane independently, then together.
16. Run targeted shuffle/repeat checks for files moved to parallel:

```powershell
npx vitest run --project node-parallel --sequence.shuffle --sequence.seed=260925
npx vitest run --project node-parallel --sequence.shuffle --sequence.seed=260926
```

17. Move any reproducibly stateful test to `node-serial`; do not add sleeps.
18. Capture three optimized full-suite runs with identical protocol and identical
    inventory hash.
19. Profile lane critical path. Record 30% target result; do not weaken tests or
    block safe topology solely for missing the target.
20. Run at least five CI-equivalent optimized samples. Derive and check in
    `performance-budget.json` with absolute `maxWallSeconds`, runner class,
    inventory hash, measurement commit, sample durations, statistic, and bounded
    variance margin. Owner approval is required if variance exceeds the declared
    limit.
21. Add a budget contract that fails when runtime exceeds `maxWallSeconds` or the
    receipt/config/inventory subject differs.
22. Run full coverage and compare thresholds, test inventory, pass/skip counts,
    and source-file coverage presence.

- Every non-E2E test executes exactly once.
- No production storage path is touched.
- Parallel workers use unique roots.
- Skipped count does not increase and no assertions are weakened.

## Risk Assessment

| Risk                                 | Observable signal                                  | Pre-decided response                                                 |
| ------------------------------------ | -------------------------------------------------- | -------------------------------------------------------------------- |
| Hidden shared state creates flakes   | Seed/repeat failure or ENOENT/port collision       | Move exact test to serial; add deterministic isolation regression    |
| Over-serialization misses target     | Serial lane dominates critical path                | Profile; isolate narrower state ownership; never drop tests          |
| Too much parallelism thrashes memory | Runtime worsens, OOM, worker exits                 | Lower bounded worker cap and remeasure                               |
| Coverage maps overwrite each other   | Missing source files or impossible percentage jump | Fail merge contract; fix filename-normalized merge                   |
| Inventory semantics change           | File/suite/test counts unexpectedly differ         | Block; reconcile reporter definitions before acceptance              |
| Historical benchmark misleads        | Fresh baseline differs materially from 1,227.75s   | Use fresh median only; keep historical value context                 |
| Baseline contaminated by RED tests   | Legacy/new inventories or config subjects differ   | Discard run; restore frozen legacy config and recapture before RED   |
| 30% target missed safely             | Complete suite improves less than 30%              | Keep absolute hard gate; profile and open reviewed optimization work |
| Absolute budget becomes stale        | Runner class/inventory/toolchain hash changes      | Invalidate receipt; remeasure both topology and budget               |

## Security Considerations

- Test workers must never point at `server/data` or `server/uploads`.
- Temp-root cleanup must prove containment before recursive deletion.
- Do not print environment secrets in benchmark receipts.
- Child-process tests inherit an allowlisted test environment where practical.
- Coverage and reporter artifacts must exclude credentials and raw imported deck
  content.
- Parallel execution must not cause tests to bind public interfaces; loopback
  only.
