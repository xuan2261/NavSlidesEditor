## 1. Trigger-extension design notes

Current accepted kinds are the Set at `shared/src/element-actions.js:3`; normalization’s kind allowlist and per-kind allowed fields are at `:35-40`, conditional schema parsing at `:46-57`, and serialization at `:60-63`. Add `show`, `hide`, `toggle`, score add/subtract, play-media, and reset-slide here with strict kind-specific fields. `shared/src/types/presentation.js:17-24` must widen `ElementAction.kind` and document target element ids/selectors (prefer explicit IDs), score variable name/amount, media target, and reset semantics.

Editor: extend `KINDS` at `client/src/components/properties/action-controls.jsx:5-8`; add widgets adjacent to existing slide/URL fields at `:55-58`, using element choices from presentation slides and the selected element’s section. Its `begin` function at `:39-43` currently seeds slide vs URL payloads only; give each new kind a clean payload rather than permitting stale incompatible keys. Action normalization is imported shared logic, so the client cannot save a draft until required parameters validate.

Runtime insertion: `presentationUsesActions` at `shared/src/htmlGenerator.js:108-115` already gates script and feedback emission. Extend `buildActionRuntimeScript` (`:195-223`), chiefly `activate` (`:209-219`), plus event delegation if triggers become non-click or media controls need gesture handling (`:220-221`). For targets, export currently has no universal element-id attribute: `buildWrapperAttrs` (`shared/src/element-renderers.js:213-219`) emits `data-id` only for autoAnimate slides, while `renderElement` (`:1043-1049`) puts it on the renderer’s wrapper. `data-export-element-id` is emitted only when `opts.exportElementIds` is true. Therefore add a stable escaped universal target-id data attribute in renderElement (or ensure exportElementIds is enabled for all interactive HTML), and make runtime target only within current slide/vertical section; avoid CSS selector interpolation, use attribute lookup / `getElementById` with proper escaping strategy.

Hidden/fragments: `renderSlideElements` removes `el.hidden` elements entirely (`shared/src/element-renderers.js:1065-1069`), so action targets configured hidden in editor cannot exist in exported DOM. Fragments remain rendered with Reveal `fragment` class and optional `data-fragment-index` (`:216-219`); Reveal’s fragment visibility state is separate from CSS `visibility`. Show/hide/toggle should define precedence with fragment state and not directly remove fragment classes; direct visibility changes may be overwritten or desynchronize fragment events. [INFERENCE] A robust approach is an independent runtime state/class or hidden attribute layer that Reveal fragment updates cannot clobber.

Score variables need runtime-owned state (e.g. keyed numeric map) and a documented presentation surface/binding so users can observe values; no existing shared score-variable contract was found. `play media` requires mapping media element IDs to nested exported `<audio>/<video>` nodes and handling rejected `play()` promises. Reset slide should define whether it resets only current slide’s runtime state/media/fragments or returns to initial Reveal state; current runtime has navigation only.

## 4. iframe sandbox change impact

Export HTML element rendering (`shared/src/element-renderers.js:357-384`) uses data URLs for non-Mermaid embeds, expressly noted as opaque-origin at `:376-378`; this confirms that data: document already has opaque origin. A sandbox with only `allow-scripts` retains script execution but strips same-origin privileges; however origin behavior for data URL is already opaque, so the critical impacts are removing script access to parent DOM/window and storage capability. In the editor canvas, `srcDoc` currently uses `sandbox="allow-scripts allow-same-origin"` (`client/src/components/canvas/canvas-element-wrapper.jsx:622-634`); stripping same-origin would change srcdoc to an opaque origin and block same-origin access/fetches and localStorage.

Template/preset findings from targeted searches: Mermaid is special-cased into srcdoc and relies on `/vendor/mermaid/mermaid.min.js` (`client/src/hooks/use-element-creation.js:28-30`, renderer special case `shared/src/element-renderers.js:366-370`); chart/LaTeX renderers also request `/vendor/...` assets (`client/src/components/element-renderers/chart-element-renderer.jsx:52-56`; `latex-element-renderer.jsx:12-14,32-35`). Those paths need accessible origin; an opaque srcdoc/data origin can make relative or root `/vendor` requests resolve differently or fail due origin/CORS. Anime/kinetic/three/math modal templates insert standalone HTML (`client/src/components/anime-js-animation-template-selector-modal.jsx:29`, kinetic `:90`, three `:46`, math insertion via `editor-modals-secondary.jsx:166-169`); search did not find parent/localStorage/postMessage references in those generated files. [INFERENCE] They are likely self-contained, but exact generated strings were not exhaustively read here. STEM presets are external provider iframe elements, not necessarily raw HTML; no evidence from this search that they depend on parent access.

Plugin iframe is already `sandbox="allow-scripts"` (`shared/src/element-renderers.js:948`) and exported host communication uses postMessage (`shared/src/htmlGenerator.js:154-193`). Search found game React iframe parent-global access in four-corners, relay-race and scattergories (`client/src/components/game-interactive/four-corners-live-game-renderer-with-timer-scoring-leaderboard.jsx:77-111`; relay `:78-95,142-155`; scattergories `:142-172`)—these are game runtime embeds and do rely on direct parent access, though distinguish from user-authored HTML iframe sandbox. Search found no postMessage implementation in the listed raw HTML template files; the confirmed postMessage bridge found is plugin runtime. Data-URL HTML render receives `<base href="<asset origin>/">` (`element-renderers.js:380-382`), so `/vendor` may resolve against its origin base, but sandbox CSP/CORS and local-file/offline behavior remain risks.

## Risks / caveats

- Current target selectors cannot reliably target ordinary element wrappers via element `id`; `data-id` is conditional on autoAnimate. Adding actions that affect other elements requires universal stable export IDs and scope/duplicate-ID handling.
- Hidden model elements are filtered out, so cannot be shown by runtime actions without changing rendering policy.
- Reveal fragment transitions can conflict with arbitrary display/visibility mutations.
- Browser-only triggers remain omitted in PPTX, warnings already generic by action kind.
- `allow-scripts` without same-origin intentionally prevents parent/storage access; root `/vendor` dependencies need an origin-aware loading strategy and browser verification, especially canvas srcdoc and offline/data URL exports.
- User-provided raw HTML is trusted in share HTML under current route behavior; sandbox restriction is defense in depth, not server sanitization.
- Content-safety.js was not present at the requested repository-root path; targeted path lookup failed. [INFERENCE] The file may reside in a subdirectory, and no claim is made that no content-safety module exists.
