## 3. Bundling/vendor closure
- `client/vite.config.js`: ordinary Vite client build (no explicit `rollupOptions.input`); `manualChunks` splits React/react-dom/router, KaTeX, lucide, Tiptap. `/vendor` proxies to API for dev and preview. An independent IIFE/library entry is technically expressible with Rollup/Vite output configuration, but a second entry alone does not guarantee it is emitted into deployable/package artifacts.
- Server serves `server/vendor` at `server/index.js:239`; Socket.IO client served from installed `socket.io-client/dist` at `:236-238`. Uploaded SVG gets a restrictive per-response CSP at `:224-228`. No general Helmet/CSP middleware appeared in server search; `/share` and `/present` routes send generated HTML without route-specific CSP (`server/routes/presentations-extras.js:91-116`; share handler is `server/index.js:288+`). Treat absent global CSP as search evidence, not a deployment-proxy guarantee.
- `shared/src/reveal-runtime-assets.js:6-37` centralizes Reveal paths and required offline paths/themes, runtime version, and copy spec. `scripts/copy-vendor.js` reads manifest, copies Reveal/KaTeX/chart/highlight/D3/socket client/etc., builds QR IIFE and calls publication. `scripts/vendor-publication.js` stages files and records path/size/SHA-256 manifest; `scripts/verify-runtime-closure.js` checks required Reveal paths/version, hashes, server require closure and optional client artifact closure. New runtime assets require integrating with vendor publication/artifact verification and offline required assets where appropriate.
- `client/vite.config.js:13-22` current manual chunk strategy is not standalone bundling; React libraries split to vendor-react chunk. Standalone runtime IIFE likely needs dedicated output with bundled deps or external globals plus explicit delivery/copy inclusion, and offline inliner support.

## 4. Offline exporter
- `generateOfflineHTML(html, options)` in `client/src/utils/offlineExport.js` (`:171+`; strict flag `:172`) handles vendor CSS and CSS `url()` dependencies, vendor JS, special chalkboard/menu patches, selected CDN maps, removes known remote font links, processes regex-matched iframe `srcdoc` and `data:text/html` iframe URLs, then initializes iframe content via inline script/blob/srcdoc, embeds `/uploads` and best-effort external image URLs, removes `<base>`.
- `strictRequiredAssets` is opt-in only when exactly `true`; required missing assets throw through `cachedFetchText`/required fetch. Optional failures substitute a comment or leave remote references depending path. Strictness is asset-manifest based, not comprehensive offline-closure validation.
- Concrete gaps: regex handles static `<script src=...>` only when src resolves to `/vendor/...` (plus known CDN mapping in iframe path); arbitrary remote/dynamic script insertions, JavaScript-created scripts, scripts referenced through unsupported schemes/relative paths, CSS imports beyond removed Google-style remote imports, runtime fetch/network APIs, and non-image uploaded resources are not closed. `srcdoc` regex expects quoted attribute and no complex HTML-parser handling; nested/dynamically created frames are not recursively discovered after runtime. Generated iframe blob/srcdoc policy can interact with CSP.

## 5. CSP / sandbox
- Electron `electron/content-security-policy.js:1-22`: allows inline JS (`script-src 'unsafe-inline'`), blob/https scripts; inline styles, blob/data/https frames; connect-src local HTTP/WebSocket plus secure network. `'unsafe-eval'` is intentionally absent. A bundled IIFE avoids eval but still needs inline runtime boot snippet unless external script.
- `server/index.js:224-228` CSP is only shown for untrusted SVG response; server search found no Helmet/global CSP for share/present. Electron policy governs desktop responses if no CSP header already exists; app code preserves existing CSP (`:17-21`).
- HTML element sandboxing relevant to runtime: React editor iframe is `sandbox="allow-scripts allow-same-origin"` (`client/src/components/canvas/canvas-element-wrapper.jsx:628-632`); generated static HTML element is a data-URL iframe (`shared/src/element-renderers.js:379-383`, prior confirmed finding), without an equivalent sandbox in that renderer. Iframe sandbox flags constrain top-level navigation/storage and scripts; combining allow-scripts+allow-same-origin for same-origin content weakens isolation and is a concrete security concern. Offline exporter rewrites srcdoc to blob/about:blank then restores srcdoc under file protocol, so test the final frame origin/sandbox behavior.

## Recommendation
Prefer (b), a vanilla-JS runtime in `shared/src`, with runtime generation/injection and explicit, narrow DOM contracts. It naturally serves generated Reveal HTML, shared pages and offline exports without requiring React/CSS/ReactDOM app assets or a Vite-generated browser module loader. It can use inline scoped styles or a shared runtime stylesheet, and communicate with the existing socket host bootstrap by defined DOM events/API.

(a) is feasible but has concrete costs/blockers:
1. Existing React renderers assume editor/client module graph and React hooks; bundling React + ReactDOM into a standalone runtime is substantial (React manual chunk currently split and large), with duplicate React risk if mounted into app-owned tree.
2. Game hooks call `useGameSocket`, use presenter host/auth role, socket-specific options and callbacks; generated HTML's bootstrap already manages authoritative host game joins (`shared/src/live-presenter-game-runtime.js`). Reusing the React implementations must reconcile duplicate socket ownership, auth/capability lifecycle and game events.
3. Four-corners/relay/scattergories directly read `window.parent.__timerStates`, which only exists under `LiveViewPage`; standalone/exported Reveal page lacks it. Need replace with runtime-local or explicit cross-window timer API.
4. Game UI/style dependencies include Tailwind utility class assumptions (`client/src/components/game-interactive/*` and related classes); Reveal HTML does not load app Tailwind stylesheet. Inline-style-heavy components may survive but classes silently lose presentation styles.
5. React game components include lazy imports and client-only modules, broad module graph, sockets, editor contexts, and app-specific global assumptions; tree-shaking by selecting renderers may not avoid all dependency weight.
6. Current static renderer emits no `[data-ns-game]` mount element or serialized props contract. Adding mounts affects HTML escaping/sanitization, IDs, slide lifecycle, repeated Reveal slide rendering and offline export script discovery.
7. CSP would permit a same-origin external IIFE under Electron, but offline exporter currently processes vendor scripts and not a new runtime asset unless added to required manifest/path rules; shared HTML served outside desktop may have deployment CSP not visible in repo.
