## Architecture decisions

1. Keep 19 canonical element discriminators. Reusable educational blocks extend `type:'game'` with explicit gameType; `quiz` is a new subtype with typed questions, not a twentieth element. All subtypes go through one shared registry with labels/defaults/capabilities; client `GAME_TYPES`, schemas, Insert, bootstrap and docs consume it. Existing ten: name-picker, hot-potato, jeopardy, four-corners, relay-race, trivia-champ, scattergories, poll, word-cloud, matching. New nine: quiz, lucky-wheel, countdown, scoreboard, memory, flashcards, sorting, crossword, word-search. Matching retains its discriminator, gaining drag/drop and local play. Final: 19 canonical element types, 19 game subtypes. Verify counts mechanically, never pin prose-only tests.
2. Shared pure configuration normalization/evaluation/reducers under `shared/src/education/`; browser DOM presenters under `shared/src/education/browser/`, dependency-free except the existing optional Socket.IO client. Bundle an IIFE with already-installed esbuild 0.25.12 (package.json:107); no React dependency, eval, dynamic import or external CDN. Publish `/vendor/navslides-education/runtime.js` and `runtime.css` through existing vendor staging/hash manifest and required-assets closure. Browser API proposed: `NavSlidesEducation.mount(root,{mode,transport,clock,random}) -> {getState,reset,destroy}`. Unit tests inject deterministic clock/random; production uses monotonic time and normal random selection. Thin React adapter mounts the SAME DOM presenter in explicit Try/Play surface. Edit canvas remains inert authoring preview; generated Present/Preview/Share/Offline all mount shared runtime directly. Replace unreachable/duplicate React play reducers after cutover.
3. Local mode works without HTTP/WebSocket or parent globals; local poll/word-cloud/matching allow one-device classroom play. Eligible live games choose Live via existing trusted query/bootstrap and capability metadata; their server is authoritative for host commands, team assignment, timers, buzz order, scoring and answer results. Disconnect preserves waiting/read-only state, never silently switches those games to local scoring. Presentation variables and classroom-local utilities remain local even in a live-enabled presenter document; variableId is not a game/player score key. Multiplayer cannot work in an offline file; UI says local classroom mode, not broken/offline network retry.
4. Shared catalog declares local/live capabilities honestly. Four corners, relay, trivia, scattergories and typed quiz gain real live support. Existing live types preserve behavior and verified question redaction; Jeopardy live scoring needs server-owned cell/turn lifecycle to remove local/server split. New memory/flashcards/sorting/crossword/word-search/lucky-wheel/countdown/scoreboard are classroom-local modules, not phone rooms or synchronized deck-variable services. Eligible live-game score/deadline authority remains a separate12/13 contract; do not promise phone participation for unsupported types.
5. Authoring vs runtime state: persisted JSON stores config and stable IDs only. Runtime owns progress, selected answers, counters, time, picker exclusions, revealed cards, scores; runtime reset/reload never mutates the saved deck. Hide/show preserve per-slide progress; pause active timers on slide leave, resume remaining time on return in local mode; live deadlines continue server-side. Full replay clears timers/listeners/pending feedback and increments session generation. Timer uses deadline/elapsed monotonic calculation, not interval decrement or window.parent polling.
6. Canonical quiz question: `{id,kind,prompt,media?,points,timeLimit,options?,answerKey,feedback:{correct,incorrect,explanation}}`; kinds single-choice, multi-choice, true-false, fill-blank, ordering, matching, image-hotspot. AnswerKey type is kind-specific, private in live public projections. Existing correctIndex configs normalize at boundary, then callers cut over; no duplicate evaluator/shim exports. Quiz points default exact-match per question, no partial-credit default; retries follow authored attempt limit, each submitted attempt has unique identity and accepted score awarded only once. Existing Hot Potato speed bonus remains explicit game policy, not accidentally applied to all quizzes. Fill-blank uses trim + Unicode NFC + optional case-insensitive matching; diacritics remain significant by default, accepted alternatives explicit. Ordering/matching use stable item IDs, never display indices. Image-hotspot uses bounded normalized 0..1 rect/circle regions and keyboard/text-region alternative. Image URL/alt obey current media safety and offline bundling.
7. Minimal click actions, not general workflow engine: add `show`, `hide`, `toggle`, `score-add`, `score-subtract`, `reset-slide`; safe per-kind schemas, no JS or CSS-selector expressions. A single action activates once on pointer or Enter/Space. Stable `data-ns-element-id` per wrapper scoped to current effective slide (top-level/vertical/master); copy/duplicate/paste remap references. Distinct `initialVisibility:'visible'|'hidden'` field for playable targets; editor `hidden` continues export omission. Fragment gate AND trigger visibility determines display; show does not override a not-yet-revealed fragment. Numeric `presentation.interactionVariables` bounded to finite score values; scoreboard renders bound score using textContent, reset-slide resets slide-local state but NOT deck score unless author config explicitly requests reset. No new user code channel.
8. Utility blocks: lucky-wheel reuses shared name-picker weighted sampling with prize labels and positive finite per-item weights; missing weights = 1; remove picked items when configured. Countdown has duration/start/pause/resume/reset and clear expiry. Scoreboard edits teams and increments/decrements/reset, can bind to deck variables. Memory uses paired text/image cards; flashcards flip and next/previous; sorting classifies into buckets; crossword accepts explicit valid authored layout plus bounded generator with actionable failure; word-search bounded seeded grid and authored words. Pointer/touch plus click-select/place + keyboard alternatives, no mandatory dragging.
9. Authored HTML remains programmable INSIDE `sandbox="allow-scripts"`, never same-origin/top navigation/popups by default. Keep built-in simulation scripts working through bundled absolute/data assets or a narrow audited message channel only when necessary, not by restoring same-origin. Plugin messaging validates event.source + instance token/message schema; opaque origins cannot rely on origin matching alone. Separate runtime adapter from raw HTML sandbox. Offline normal Download uses the supported portable export path; hosted URL/share remains hosted. Strict file export embeds known required static resources recursively incl scripts/styles/fonts/images/audio/video/question images/plugin files; bounded dynamic dependencies require explicit manifest (built-in simulations supply it). Arbitrary runtime network/unknown dynamic dependencies cause structured actionable errors for portable export, not a success with broken assets. Offline cannot conceal local answer keys; live participant projections must.
10. Migrate only known built-in quiz IDs (quiz-multiple-choice, quiz-true-false, quiz-fill-blank, quiz-ordering, quiz-matching) to native blocks; no regex parsing/rewrite of arbitrary user HTML decks. Keep built-in template IDs, slide titles and lesson meaning. Existing six simulations (Logic Gate, RLC Frequency, PID Controller, Bode Plot, 3-Phase Power, Gear Train) become reusable library presets with local controls verified; sandbox/asset refactor not invented new physics scope. Preserve arbitrary user HTML unchanged except isolation policy with visible compatibility notice.
11. PPTX/PDF stay static by format limits; render actual question/board snapshot, never interactive claim. Matching/questions answer keys are omitted from default public snapshot unless explicit teacher reveal view. Extend existing warnings; no unrelated native PPTX implementation.
