**Scanner's actual schema acceptance.** `scripts/verify-container-supply-chain.js:8-60` accepts SBOM with either string `spdxVersion` starting `SPDX-` and nonempty `packages`, or `bomFormat === 'CycloneDX'` and nonempty `components`. Policy must have schemaVersion numeric `1`, `failSeverities` and `exceptions` arrays. Each exception requires truthy `id` and `reason`, a parseable `expires` later than verifier `now`; approval matches exact vulnerability ID and, when provided, exact package name. Findings are taken from Trivy-like `report.Results[]`, flattening `Vulnerabilities[]`; `report`/`Results` absence acts as an empty list. Only findings whose Severity exactly matches a configured fail severity and lack matching exception fail. Scanner does not validate Trivy report schema, severity vocabulary, scan completeness, result target, exception uniqueness, or policy hash provenance; malformed/empty report can pass. It records status, image digest, browser versions/revision, counts and hashes. Image digest must match `sha256:` plus 64 lowercase hex and expected digest; browser needs Playwright match, nonempty Chromium revision and executable path, exact expected revision. Potential policy gap to capture in plan: fail-closed report/schema/completeness acceptance and nonempty actual findings inventory / scanner metadata (design choice to derive from existing tool output; avoid claiming current validation).
