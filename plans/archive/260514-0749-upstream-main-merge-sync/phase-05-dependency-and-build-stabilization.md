## Overview

- Priority: P1
- Status: Pending
- Goal: stabilize dependencies and prove merged code compiles.

## Key Insights

- Repo uses npm and `package-lock.json`.
- Lockfile should be generated by npm, not hand-edited.
- Build is the first hard gate after conflict resolution.

## Requirements

- Functional:
  - Install/regenerate dependencies if needed.
  - Build client successfully.
  - Fix compile errors caused by merge.
- Non-functional:
  - Do not upgrade unrelated packages beyond merge need.
  - Keep fixes scoped.

## Architecture

```text
merged source -> npm install -> lockfile stable -> npm run build
```

## Related Code Files

- Modify:
  - `package.json` if conflicts require manual combination.
  - `package-lock.json` through `npm install`.
  - Source files only to fix merge-caused build errors.
- Create: none expected.
- Delete: none expected.

## Implementation Steps

1. Install dependencies:
   ```powershell
   npm install
   ```
2. Inspect package changes:
   ```powershell
   git diff -- package.json package-lock.json
   ```
3. Build:
   ```powershell
   npm run build
   ```
4. If build fails:
   - Read first real error.
   - Fix root cause in smallest affected file.
   - Re-run `npm run build`.
5. Check status:
   ```powershell
   git status --short
   ```

## Risk Assessment

- Risk: package lock churn too large.
  - Mitigation: inspect lockfile diff; ensure it comes from upstream/dependency resolution.
- Risk: build failure hidden by noisy logs.
  - Mitigation: fix first root error, not downstream errors.

## Security Considerations

- Review new dependencies for suspicious packages.
- Do not add tokens to npm config.
